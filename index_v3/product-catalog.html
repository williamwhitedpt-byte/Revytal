Product Catalog

The catalog has to be useful before it is big.

Revytal should not start by dumping every possible supplier row into a clinic workflow. The first pilot catalog needs to be curated, understandable, and safe enough for real recommendations.

Pilot guardrail

Broad reference is not the same as app-ready.

The expanded product database can inform search and sourcing. The pilot should start from a reviewed subset.

Bracing

Exact support products

Braces, sleeves, straps, and fit-dependent items need clear variant handling and clinical review notes.

Mobility

Bands and home-plan basics

The simple products still matter. They are often the easiest way to test whether the handoff works.

Recovery

Topicals and recovery tools

These need clear patient-facing use notes and supplier/rights checks before they become catalog staples.

Clinical review

Higher-caution items

Traction devices, spinal braces, post-op products, and HCPCS-coded items should not slip into a pilot casually.

What each product row needs

The point is not to make a spreadsheet look impressive. The point is to make sure a clinician can recommend an item without creating a support problem five minutes later.

Product identity

Name, supplier SKU, variants, image, and patient-facing description.

Clinical context

Body region, use case, sizing notes, contraindication cautions, and internal review status.

Fulfillment reality

Availability, shipping, returns, supplier terms, image rights, and pricing authority.
